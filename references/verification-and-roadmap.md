# 五态验收生命周期、高风险语义修改追踪表与统一日志脱敏规范（v1.1.3）

## 本地使用说明

科研润色以 [写作入口](../SKILL.md) 的交付规则为准。下文的状态和固定追踪表用于有此要求的写作流水线。格式状态只反映脚本自身检查。

- `--check` 的格式提示需要人工复核。v1.1.3 可误判合法的数字参考链接，且对部分以数字起首的行内数学保护不完整。用于科研稿时按只读结果核对原文件。脚本筛出的科学限定也有漏标。
- `--fix` 有可能输出改错的引用和公式，即使结果报告通过。已有锚点错误时，原版也可能先替换目标再返回失败。批量试验使用副本和独立输出路径，核对每项差异后再决定采纳。
- 诊断按源稿的保密要求留存。`q4_items` 可包含原文和路径。提示词审计会回显被命中的原文。使用 `--diff` 或 JSON 也需独立检查输出后再分享。

Python 确定性脚本与单元测试只负责安全脱敏、写前预重检文件保护与局部启发式候选提示，**绝不能跨级虚报状态，也绝不能将未执行的在线模型评测写成“已通过”**。

## 一、五阶段结果生命周期（Strict Pipeline Stage Transitions）

任何经 `clear-voice` 处理的产物必须严格按实际完成的验证动作标注状态，禁止自动跨级晋升：

1. **`Drafted`（草稿/阻断态）**：初稿刚生成，或存在 `SEC-01` 安全阻断、未解除的 `Formatting` 错误、只读文件/悬空软链接/写前预重检失败。所有退出码 `2` 的分支在 `--json` 模式下统一输出合法 JSON（`pipeline_stage: "Drafted"`, `passed: false`, `gate_passed: false`）。
2. **`Preflight Passed`（只读预检通过）**：执行 `prose_lint.py --check`（或内存只读检查）通过了安全与确定性格式检查，但**尚未执行目标文件落盘、磁盘回读与二次校验**。
3. **`Deterministic Checks Passed`（写盘确定性校验通过）**：执行 `prose_lint.py --fix` 先在临时文件上完成回读与二次重检零残留验证，再原子替换目标文件、保持原有文件权限（如 `0644`），并通过最终句柄回读与锚点同构校验。**这是 Python 脚本允许返回的最高状态**。
4. **`Semantic Review Passed`（语义复核通过）**：必须由实际语义审查行为确认：完成改写前后五维 Fact Ledger 对照、全部 `Q4_CANDIDATE` 局部片段裁决，以及极性、不确定度、因果强弱与归属关系零漂移复核（Python 严禁自动输出此状态）。
5. **`Human Approved`（人工签收完成）**：必须由人类审阅人复核 `Semantic Change Trace`（高风险语义修改追踪表）、路径警告与 `【需确认】` 事项后签收确认（任何自动化工具严禁自动输出此状态）。

## 二、`Semantic Change Trace`（高风险语义修改追踪表）标准五列结构

在 `review` 模式及提请 `Human Approved` 签收时，所有涉及 `Q2 / Q3-A / Q3-B / Q3-C` 或跨句重组的高风险语义修改必须按以下五列表头逐条列示：

| 位置 | 修改前原文 | 修改后表述 | 分流类别 (Q1-Q4/结构) | 语义风险确认 |
| :--- | :--- | :--- | :--- | :--- |
| 第 2 节 / L18 | 团队已实现 99.9% 保真度（非本公司实测） | 创始人在高校读博期间曾测得 99.9% 门保真度；公司样机尚在联调 | `Q3-B`（主体归属前置） | 数值 99.9% 保留，主体归属已与源证据对齐 |

## 三、统一凭据与路径脱敏及日志留存规则

1. **统一先验脱敏引擎（`redact_sensitive_text`）**：`SEC-01` 诊断片段、`FixRecord` 与 `--diff` 共用同一套脱敏顺序：
   - **第一步（最高优先级）**：先拦截并脱敏多行私钥块（含 `ENCRYPTED / PGP PRIVATE KEY`）、显式 API 密钥（`sk-*`、`ghp_*`、`AKIA*`、`AIza*`、`hf_*`、`glpat-*`、`npm_*`、Slack Token/Webhook、JWT）、URL 内嵌账密与查询密钥（`redis://:pass@host`、`?key=`、`?X-Amz-Signature=`）、认证头（`Bearer/Basic`）以及带上下文标签的凭据（含 `api_key = <hex>`、`client_secret = <UUID>` 及 JSON 引号键值），防止良性哈希/URL 白名单提前掩护带标签密钥。
   - **第二步（良性科学工程标识符保护）**：保护合法的 `DOI`、`arXiv`、`ORCID`、`UUID`、纯十六进制摘要（`SHA-256 / Git SHA`）、生信与临床编号（`NCT / GSE / NM_ / ENSG`）、`CVE` 以及自然驼峰/蛇形工程命名与系统配置路径（如 `SuperconductingQubitControllerV2026`、`Tip4pIceNucleation230K2000ns`、`unit_test_coverage_report`、`pwd = /opt/envoy/conf`），零误杀放行。
   - **第三步（未知高熵凭据与全平台路径脱敏）**：拦截高熵混合未知 Token，并默认脱敏含空格用户名/卷名、无尾斜杠主目录、隐藏凭据目录（`~/.ssh`、`~/.aws`、`~/.config`）、临时目录（`/private/var/folders/...`）与 UNC 共享路径，同时不篡改实际写出的正文文件。
2. **同密级留存与清理**：`FixRecord` 与 `Diff` 与源文档同属相同安全密级，禁止提交至公开仓库，在 `Human Approved` 签收后及时清理临时诊断文件。
